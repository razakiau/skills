# Foundry v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `skills/foundry`, one skill that gives a repo a stage, maps the stage's themes to providers, writes the minimum skeleton, and keeps it true. It has a router, eight commands, a bundled Node script and a vendored POSIX `sh` doc check.

**Architecture:** `SKILL.md` is a short router; each command has its own reference file. `scripts/foundry.mjs` (Node, no dependencies) does everything that must be exact:
- stage signals;
- reading and writing `.agents/foundry.json`;
- rendering templates;
- vendoring the doc check;
- digesting Copilot transcripts.

`templates/doc-check.sh` is copied into each repo as `.agents/doc-check.sh`, so the gate runs in CI without the skill.

**Tech Stack:** Node ≥ 20 (ESM `.mjs`, `node:test`, `node:fs`, `node:child_process`), POSIX `sh` with `grep`, `sed`, `find`, `awk`. No npm dependencies.

**Spec:** `docs/superpowers/specs/2026-11-01-foundry-design.md`. Evidence for each choice: `docs/superpowers/specs/2026-11-01-foundry-sources.md`.

## Global Constraints

- **One skill-list entry**, `name: foundry`. Its description is ≤ 300 characters and triggers on starting a project, auditing a repo's setup, and "is this ready for users". It does not trigger on a plain feature request.
- **`scripts/foundry.mjs`** imports only `node:*` modules, and its tests use `node --test`. It follows `skills/strategic-programming/scripts/sp.mjs`:
  - dispatch on `process.argv[2]`;
  - a usage line on stderr with exit 2 for an unknown command;
  - errors print `foundry: <first line>`.
- **`templates/doc-check.sh`** is POSIX `sh` (no bash-isms, `#!/bin/sh`, `set -eu`). It uses only `grep`, `sed`, `find` and `awk`, and its second line is `# foundry doc-check v<semver>`.
- **Stages:** `explore`, `product`, `live`, `scale`.
- **Stage required files** (spec, "Stages"):
  - explore: `AGENTS.md`;
  - product adds: `PRODUCT.md`, `docs/decisions/index.md`, `GLOSSARY.md`, `ARCHITECTURE.md`, `.agents/code-map.md`, `DESIGN.md` (only when the repo has UI), `CONSTRAINTS.md`;
  - live adds: `docs/threat-model.md`, `docs/runbooks/`;
  - scale adds nothing required (only audited).
- **AGENTS.md budget:** default 100 lines, stored as `agents_md.budget_lines`.
- **AGENTS.md always contains this exact sentence:** `When this file and the code disagree, the code wins: say so, and propose the fix to this file.`
- **AGENTS.md workflow rule** (exact copy): `A product-level decision made anywhere (a brainstorm, a spec, a review, a fix round) gets a decision file in docs/decisions/ and an update to PRODUCT.md in the same change. Code-level choices stay in the spec or the PR.`
- **`init` never rewrites an existing AGENTS.md.** It records `agents_md.state: "unmigrated"`, and the budget rule then warns instead of failing.
- **Never install a skill or MCP server.** Recommendations name the provider, why, a link and its license. On the owner's machine (`~/.agent-skills/sources.yaml` or `/opt/agent-skills/sources.yaml` exists), they are proposed as a store PR.
- **Never print secret values.** The transcript digest drops tool output bodies and keeps only tool names and argument key names.
- **Licenses named when recommending:** Shannon AGPL-3.0, Trail of Bits skills CC-BY-SA-4.0.
- **Prose** in SKILL.md, references and templates follows `skills/no-slop`: no em or en dashes in prose.

## Review Focus

- **A repo that isn't git, or has no commits yet:** `signals` must report `commits: 0` and still propose `explore`, not crash. Pinned in Task 2.
- **A repo with an existing long AGENTS.md** (e.g. 400 lines): `init` must leave it byte-identical, and `check` must warn but exit 0. Pinned in Tasks 3 and 4.
- **A non-Node repo** (Rust, Python, Ansible): `init` must wire `check` into the tool the repo already uses. With no task runner at all, it falls back to `.agents/check.sh`, never creating `package.json`. Pinned in Task 4.
- **Links with anchors, relative `../` paths, and URLs in docs:** the doc check must resolve `path#anchor` to `path`, resolve relative to the linking file, and skip `http(s):`/`mailto:`. Pinned in Task 3.
- **Copilot transcripts holding secrets in tool output:** the digest must never include `tool.execution_complete` result text. Pinned in Task 7.

  - `State` shape:
    ```json
    {
      "version": 1,

      "doc_check_version": "string"

    ```

### Task 2: Stage signals

**Files:**
- Modify: `skills/foundry/scripts/foundry.mjs`
- Test: `skills/foundry/scripts/foundry.test.mjs`

**Interfaces:**
- Consumes: `readState` (Task 1).
- Produces:
  - `export const REQUIRED: Record<Stage, string[]>`, cumulative per stage: the Global Constraints list, with `DESIGN.md` included and filtered by `has_ui` at use.
  - `signals(top: string, opts?: { sessionsRoot?: string }): Signals` and CLI `node foundry.mjs signals [--json]`.
  - `Signals` shape:
    ```
    { commits: number, first_commit: string|null, age_days: number,
      files: Record<requiredFile, boolean>, has_ui: boolean, deployed: string[],
      auth_code: string[], sessions: number|null, proposed: Stage, reasons: string[] }
    ```
- Detection rules (the agent shows every reason to the owner; thresholds are the builder's, these are the v1 values):
  - `has_ui`: any of `*.tsx`, `*.jsx`, `*.vue`, `*.svelte` or `*.html` under a non-test path, or a `web/`/`apps/web`/`frontend/` directory.
  - `deployed` lists the evidence found:
    - `.github/workflows/*` containing `deploy`, `docker/build-push-action` or `ghcr.io`;
    - `compose.y*ml`/`docker-compose.y*ml` with `ports:`;
    - `Dockerfile`;
    - a `https://` URL in README.md that isn't github.com.
  - `auth_code`: paths matching `/(auth|session|login|tenant|rbac|permission)/i`, first 5.
  - `sessions`: the count of `~/.copilot/session-state/*/workspace.yaml` whose `cwd:` or `git_root:` starts with `top`, or whose `repository:` equals the repo's `origin` slug. `null` when the root is missing. `opts.sessionsRoot` overrides the root for tests.
  - `proposed`:
    - `scale` if the state already says scale;
    - else `live` if `deployed.length > 0` and (`auth_code.length > 0` or the README names users);
    - else `product` if `commits >= 30`, or `age_days >= 7`, or `sessions >= 3`, or `PRODUCT.md` exists;
    - else `explore`.
  - The stage never moves down automatically: if the state's stage is higher, `proposed` is that stage, with the reason `recorded stage is higher; propose a lower one only with the owner`.

- [ ] **Step 1: Write the failing tests**
  - `signals: empty repo proposes explore`: `makeRepo({'a.txt':'x'})` gives `proposed === 'explore'`, `commits === 1`, `has_ui === false`.
  - `signals: non-git dir`: a temp dir without git gives `commits === 0` and `proposed === 'explore'`, with no throw.
  - `signals: 30 commits proposes product`: loop 30 commits; `proposed === 'product'` and `reasons` includes `30 commits`.
  - `signals: deploy workflow + auth proposes live`: files `.github/workflows/ci.yml` containing `docker/build-push-action` and `src/auth/login.ts`; `proposed === 'live'`.
  - `signals: sessions counted by cwd`: a fixture sessions root with 3 `workspace.yaml` (two matching cwd, one other) gives `sessions === 2`.
  - `signals: never proposes lower than recorded`: state stage `live` in an empty repo gives `proposed === 'live'`.
  - `signals: has_ui from tsx`.
- [ ] **Step 2: Run them and see them fail.** Run `node --test skills/foundry/scripts/foundry.test.mjs`.
- [ ] **Step 3: Implement `signals`.** Walk the tree with `git ls-files` when in git, else `readdirSync` recursive. Skip `node_modules` and `.git`.
- [ ] **Step 4: Run the tests and see them pass.**
- [ ] **Step 5: Commit** `feat(foundry): stage signals`.

### Task 3: The vendored doc check

**Files:**
- Create: `skills/foundry/templates/doc-check.sh`
- Test: `skills/foundry/scripts/foundry.test.mjs` (runs the script with `spawnSync('sh', ...)` against fixture repos)

**Interfaces:**
- Produces: `sh .agents/doc-check.sh [repo_root]`, which defaults to the current directory.
  - Reads `.agents/foundry.json` with `sed`/`grep` (no `jq`), taking `stage`, `has_ui`, `agents_md.budget_lines` and `agents_md.state`.
  - Prints one line per finding, `doc-check: FAIL <rule>: <detail>` or `doc-check: WARN <rule>: <detail>`.
  - Ends with `doc-check: N fail, M warn`.
  - Exit 1 if any FAIL, else 0.
- Rules and their names:
  - `link`: a Markdown link `](target)` in `AGENTS.md`, `PRODUCT.md`, `ARCHITECTURE.md`, `GLOSSARY.md` or `docs/decisions/index.md` whose local target doesn't exist. Strip `#anchor`, resolve relative to the linking file's directory, skip `http:`, `https:` and `mailto:`.
  - `command`: each command inside a `` ```sh `` block under an AGENTS.md heading containing `Check` or `Commands`. Take the first word. Exempt shell builtins (`cd`, `export`) and `sh`/`node`/`npx`/`pnpm`/`npm`/`cargo`/`make`/`mise`/`uv`/`python3`. When the first word is `sh` or `node`, the script path that follows must exist. Any other first word must be found by `command -v`, or be a script path that exists.
  - `decisions`: every `docs/decisions/NNNN-*.md` except `0000-template.md` must be linked from `docs/decisions/index.md`, and every link there must exist.
  - `budget`: `AGENTS.md` line count > `budget_lines` is a FAIL, or a WARN when `agents_md.state` is `unmigrated`.
  - `required`: each stage-required file (Global Constraints) missing is a FAIL. `DESIGN.md` is required only when `has_ui` is true.
  - `precedence`: AGENTS.md lacks the exact precedence sentence: FAIL (WARN when unmigrated).

- [ ] **Step 1: Write the failing tests.** Each test builds a fixture repo that passes, breaks one thing, and asserts the FAIL line. A check that can't fail proves nothing.
  - `doc-check: clean product repo passes`: all required files present, valid links, `budget_lines: 100`; exit 0, last line `doc-check: 0 fail, 0 warn`.
  - `doc-check: broken link fails`: AGENTS.md links `[x](docs/missing.md)`; exit 1, line `doc-check: FAIL link: AGENTS.md -> docs/missing.md`.
  - `doc-check: anchor and ../ resolve`: `docs/decisions/index.md` links `[a](../../PRODUCT.md#goals)`; no link finding.
  - `doc-check: URLs skipped`: `[s](https://example.com/x)`; no link finding.
  - `doc-check: unknown command fails`: AGENTS.md `## Check` block `foo-not-a-command --x`; FAIL `command`.
  - `doc-check: decision not in index fails`.
  - `doc-check: over budget fails when migrated, warns when unmigrated`: 150-line AGENTS.md; with `state: migrated` exit 1, with `unmigrated` exit 0 and a `WARN budget` line.
  - `doc-check: DESIGN.md required only with UI`.
  - `doc-check: missing precedence sentence fails`.
  - `doc-check: runs under dash`: if `/bin/dash` or `busybox sh` exists, run the clean fixture with it and expect exit 0; otherwise `t.skip('no dash')`.
- [ ] **Step 2: Run them and see them fail.** Run `node --test skills/foundry/scripts/foundry.test.mjs`.
- [ ] **Step 3: Write `templates/doc-check.sh`** with `# foundry doc-check v1.0.0` on line 2. Use `find`, `grep -o '](\([^)]*\))'`, and `awk` for the line count and the fenced-block scan.
- [ ] **Step 4: Run the tests and see them pass.** Also run `shellcheck -s sh skills/foundry/templates/doc-check.sh` if installed. Expected: no errors.
- [ ] **Step 5: Commit** `feat(foundry): vendored POSIX doc check`.

**Files:**

**Interfaces:**
- Consumes: `readState`/`writeState` (Task 1), `signals` (Task 2), `templates/doc-check.sh` (Task 3).
- Produces: CLI `node foundry.mjs init-files --stage <stage> [--name <repo name>] [--skip <path>,...] [--dry-run]`.
  - It writes only files that don't exist.
  - It writes templates only for the files foundry owns or falls back on: `AGENTS.md`, `PRODUCT.md`, `ARCHITECTURE.md`, `GLOSSARY.md`, `docs/decisions/index.md` with `docs/decisions/0000-template.md`, `CONSTRAINTS.md`, `docs/threat-model.md`, and `docs/runbooks/README.md`.
  - `--skip` leaves out paths whose provider will write them (for example `GLOSSARY.md` when domain-modeling is installed).
  - It never writes `DESIGN.md` (owned by Impeccable) or `.agents/code-map.md` (owned by strategic-programming). `init.md` queues them, with the provider or the fallback questions. It prints `created <path>`, `kept <path> (exists)` or, for an existing AGENTS.md, `kept AGENTS.md (exists, unmigrated)`.
  - It writes `.agents/foundry.json`. On a repo with no state, it uses the signals' `has_ui`, budget 100, `agents_md.state` (`unmigrated` if AGENTS.md existed, else `migrated`), and `doc_check_version`.
  - It copies `doc-check.sh` to `.agents/doc-check.sh`.
  - It wires `check`, in this order:
    1. `package.json` exists: add `"check": "<existing test/lint scripts joined by &&> && sh .agents/doc-check.sh"`, or only the doc check when there are none. Leave an existing `check` script untouched and print `kept package.json check (exists)`.
    2. `mise.toml` exists: add `[tasks.check]` with `run = "sh .agents/doc-check.sh"` appended to any existing test task.
    3. `Makefile` exists: add a `check:` target.
    4. `Cargo.toml` with no task runner: write `.agents/check.sh` running `cargo fmt --check && cargo clippy -- -D warnings && cargo test && sh .agents/doc-check.sh`.
    5. Otherwise: write `.agents/check.sh` running only the doc check.
  - `vendorDocCheck(top): 'created'|'updated'|'current'` compares the vendored version line with the template's.
- Template content rules:
  - `AGENTS.md` has headings: `# Working on <name>`, `## Check`, `## Verify`, `## Where things are`, `## Workflow`. It contains the precedence sentence and the workflow rule verbatim. At stage product and later, it also contains this exact line: `The reviewer of each change also reads it for access control, input handling and secrets, using the security provider when one is installed.` It stays under 40 lines, and its `## Where things are` links only to files that exist for the stage. `{{name}}`, `{{check}}` and `{{links}}` are filled by the script.
  - The other templates are short prompts for the interview to fill, each under 40 lines.
  - `ARCHITECTURE.md` follows matklad: bird's eye view, code map (links to `.agents/code-map.md`), invariants, boundaries.

### Task 6: Command references: router, init, audit, grow, providers, check

**Files:**
- Create: `skills/foundry/reference/{routing.md,init.md,audit.md,grow.md,providers-cmd.md,check.md}`
- Test: `skills/foundry/scripts/foundry.test.mjs` (link and script-command consistency)

**Interfaces:**
- Consumes: the CLI commands `state`, `signals`, `init-files`, `vendor-check` (add `node foundry.mjs vendor-check`, which prints the `vendorDocCheck` result), and Task 5's references.
- Each reference is a procedure with a "Done:" line per step, like `strategic-programming/SKILL.md`. It contains:
  - **routing.md:** run `signals --json`; state the proposed stage, every reason, missing required files, queued interviews whose moment has come, and AGENTS.md state. Offer the next command. Never run a command without the owner's yes.
  - **init.md:**
    1. Confirm the stage with the owner.
    2. Run the intent interview (provider for `intent`, else the PRODUCT.md template questions) and write PRODUCT.md.
    3. Run `init-files --stage <s> --skip <files whose provider is installed>`.
    4. Queue the other interviews in `foundry.json.queue`, each with its provider and its moment:
       - design brief and DESIGN.md: before the first screen (Impeccable `init` and `document`, else the fallback questions);
       - code map: at the first change that touches two modules (strategic-programming, else its `reference/code-map.md` template);
       - glossary: when a second domain term is disputed, or at the first decision;
       - quality bar: before the first PR at product;
       - threat model: on entering live.

       The router judges when a moment has come; the script only stores the text.
    5. With an existing AGENTS.md, propose the migration diff (keep map items; move each other section to its owning file or a skill; list deletions with reasons), apply it only after the owner approves, then `state --set agents_md.state=migrated`.
  - **audit.md:**
    1. Run `signals` and `check`.
    2. Read `themes.md` for the stage.
    3. Report each theme as covered (which file or provider), missing or stale.
    4. List rules in CONSTRAINTS.md and AGENTS.md written as prose that a script could check, and propose each check.
    5. Report readiness gaps for the current tier from `readiness.md`. Read it; never paste it into a build prompt.
    6. Report the doc-check version drift. Writes nothing.
  - **grow.md:** confirm the next stage, then `state --set stage=<next> --set stage_reason=...`. Run `init-files --stage <next>`. On entering live: queue the threat model, set `readiness_tier=1`, and propose the CI security scan (semgrep or the stack's equivalent, plus a dependency scan) as a diff the owner approves.
  - **providers-cmd.md:**
    1. For each theme of the stage, search the agent's own skills and MCP tools, including `mcp_tool_search`/`local_tool_search` when present.
